# Speak to Fight 家园系统实施计划

## 目标架构

`HomeScene` 只负责模块编排；输入、玩家、镜头、世界数据、空间查询、交互、语音桥、调试和存档状态分别由独立模块负责。Phaser 自带 Scene Manager 继续作为应用场景管理器。

## 分阶段实施

### Phase 0：审计与基线

- 识别静态菜单家园与技术设计的差距。
- 复用现有餐厅、训练、战斗、语音与存档能力。
- 保持 1280×720 横屏逻辑坐标和既有美术语言。

### Phase 1：家园世界与角色

- 建立 2200×1200 世界坐标和世界边界。
- 以数据定义建筑，入口作为独立实体。
- 加入带独立碰撞体的家园角色和平滑八方向移动。
- 加入建筑碰撞和代码绘制的道路、植被、建筑与入口标记。

### Phase 2：统一输入与镜头

- 支持键盘、手柄、移动虚拟摇杆和设备方向。
- 自动选择最近活动输入源，并允许切换固定模式。
- 为体感加入授权、低通滤波、死区、校准和屏幕方向映射。
- 加入帧率无关镜头跟随、移动前瞻和边界限制。

### Phase 3：交互与功能场景

- 用空间网格减少交互候选查询范围。
- 使用距离、朝向和入口优先级选择唯一目标。
- 统一执行场景切换、睡眠恢复和设置入口。
- 新增医院强化场景与书架掌握度场景。

### Phase 4：语音桥与导航

- 将既有 Realtime / Browser / Mock 语音能力接入家园。
- 将自然语言解析为有限目的地允许列表。
- 只产生导航标记或当前交互，不允许模型直接执行任意场景命令。
- 离开场景时停止监听并移除事件订阅。

### Phase 5：存档、调试与兼容

- 存档升级为 v6，新增 `home` 状态并迁移旧存档。
- 每五秒和关键交互时保存位置、朝向与配置。
- 加入 F3 调试层，显示 FPS、状态、输入源、体感值、碰撞和空间网格。
- 支持 `prefers-reduced-motion`，降低循环动画和镜头反馈。

### Phase 6：测试与验收

- 单测输入仲裁、存档迁移、空间索引、交互评分、世界数据和语音命令。
- 执行 TypeScript、Vite 生产构建和完整 Vitest 测试。
- 在桌面和手机横屏检查移动、交互、场景往返和位置恢复。

## 验收标准

- 家园可以连续八方向移动，且不受横版战斗重力影响。
- 建筑碰撞稳定，所有入口均可被距离与朝向系统选中。
- 餐厅、医院、训练、书架、远征、休息和设置均可到达。
- 自动输入能在键盘、手柄、触控和体感间正确仲裁。
- 旧存档载入后自动升级，非法位置不会导致角色出生在世界外。
- 语音可以标记已允许的目的地，未知命令不会触发场景行为。
- 离开并返回家园后恢复最近位置和朝向。
